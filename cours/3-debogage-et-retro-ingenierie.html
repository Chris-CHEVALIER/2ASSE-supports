GDB en profondeur

Débogage et rétro-ingénierie

Avancer dans un programme

Sur un programme compilé en C, ni évite d'entrer dans printf ou strlen, ces fonctions de la bibliothèque standard qui comptent des centaines d'instructions.

Modifier un programme pendant son exécution

GDB ne se contente pas d'observer : il peut changer l'état du processus.

CommandeEffet
set $rax = 1change un registre
set $rip = 0x401268saute ailleurs
set {char}0x404040 = 'A'écrit un octet en mémoire
call (int)puts("Coucou")appelle une fonction
Une vérification de mot de passe se termine presque toujours par un saut conditionnel. Il suffit de changer le résultat d'une comparaison (set $rax, ou l'indicateur ZF) pour passer de l'autre côté.

Conséquence : une protection qui s'exécute sur la machine de l'utilisateur peut toujours être contournée par cet utilisateur. Les vraies vérifications se font sur un serveur.

set $eflags |= 0x40 met ZF à 1 (ZF est le bit n° 6 de eflags).

#2

Du C à l'assembleur

Débogage et rétro-ingénierie

Ce que produit un compilateur


int add_bonus(int grade)
{
    int bonus = 2;
    return grade + bonus;
}

int main(void)
{
    return add_bonus(14);
}


$ gcc -O0 -S -masm=intel bonus.c

-S s'arrête à l'assembleur (fichier bonus.s), -masm=intel choisit la syntaxe du cours, -O0 désactive l'optimisation.


add_bonus:
    push    rbp
    mov     rbp, rsp
    mov     DWORD PTR -20[rbp], edi
    mov     DWORD PTR -4[rbp], 2
    mov     edx, DWORD PTR -20[rbp]
    mov     eax, DWORD PTR -4[rbp]
    add     eax, edx
    pop     rbp
    ret
main:
    push    rbp
    mov     rbp, rsp
    mov     edi, 14
    call    add_bonus
    pop     rbp
    ret
On reconnaît tout : l'argument arrive dans edi (convention System V, int = 32 bits), le résultat repart dans eax, call et ret. -20[rbp] est l'écriture de gcc pour [rbp - 20].

Lire une fonction compilée

  • Prologue : push rbp puis mov rbp, rsp. rbp devient le repère fixe de la fonction
  • Variables locales : sur la pile, sous rbp. Ici bonus est en [rbp - 4] et la copie de grade en [rbp - 20]
  • Épilogue : pop rbp (ou leave) puis ret
  • DWORD PTR : la taille de la case, comme dword en NASM. Un int fait 4 octets

Avec l'optimisation (gcc -O2) :


add_bonus:
    lea     eax, 2[rdi]
    ret
main:
    mov     eax, 16
    ret

Le compilateur a supprimé la variable, calculé 14 + 2 d'avance et même évité l'appel. Un binaire optimisé ressemble beaucoup moins à son code source.

Les astuces des compilateurs

Pour aller plus vite, les compilateurs remplacent les opérations coûteuses par des équivalents. Il faut savoir les reconnaître.

Code machineSignificationPourquoi
xor eax, eaxeax = 0instruction plus courte que mov eax, 0
lea eax, [rdi + rdi*2]eax = rdi × 3lea calcule sans toucher aux indicateurs
shl rax, 5 puis sub rax, rdxrax = rdx × 32 − rdx = rdx × 31un décalage est plus rapide qu'une multiplication
mul par une grande constante puis shrune division par une constantediv est très lente : on multiplie par l'inverse
test eax, eax puis je« si eax vaut 0 »plus court qu'un cmp eax, 0

Décaler de n bits vers la gauche multiplie par 2n : shl rax, 5 multiplie par 32.

#3

Analyser un binaire inconnu

Débogage et rétro-ingénierie

Une démarche en trois temps

1. Reconnaître
  • file : type, architecture
  • strings : textes lisibles
  • nm : noms des fonctions
2. Analyse statique
  • objdump -d -M intel : désassembler sans exécuter
  • repérer les comparaisons et les sauts
3. Analyse dynamique
  • GDB : exécuter, s'arrêter, observer les registres et la mémoire
  • vérifier ses hypothèses
Commencez toujours par le plus simple : un mot de passe en clair se trouve en une commande avec strings.
Notez au fur et à mesure ce que vous trouvez : adresses, valeurs, hypothèses. C'est votre compte rendu.

Outils professionnels : Ghidra (libre, publié par la NSA), Rizin et Cutter (libres), IDA (commercial). Ils reconstruisent même un pseudo-code C.

Reconnaître le terrain


$ file pin
pin: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, ...
$ strings pin | grep -i acc
Accès autorisé
Accès refusé
$ nm pin | grep " T "
0000000000401196 T main
  • file : un exécutable x86-64 lié dynamiquement. Il utilise la bibliothèque C du système (printf, scanf…)
  • strings : les messages affichés trahissent le rôle du programme. Ici, un contrôle d'accès
  • nm : la liste des symboles (noms de fonctions et de variables). T désigne une fonction du code

Un binaire peut être « strippé » (strip) : ses symboles sont supprimés et nm n'affiche plus rien. L'analyse reste possible, mais plus longue.

Trouver le code PIN

  • scanf range le nombre saisi en [rbp-0xc]
  • Ce nombre est comparé à 0x1092
  • S'il est différent (jne), on saute au message « Accès refusé »
0x1092 = 4096 + 144 + 2 = 4242 : le code PIN.

Les lignes fs:0x28 du début et de la fin de main sont le canari de pile, une protection présentée plus loin.


4011c5:  lea    rax,[rbp-0xc]
4011c9:  mov    rsi,rax
4011cc:  lea    rax,[rip+0xe3d]   # "%d"
4011d3:  mov    rdi,rax
4011d6:  mov    eax,0x0
4011db:  call   4010a0 <__isoc99_scanf@plt>
4011e0:  cmp    eax,0x1
4011e3:  je     4011ec <main+0x56>
  ...
4011ec:  mov    eax,DWORD PTR [rbp-0xc]
4011ef:  cmp    eax,0x1092
4011f4:  jne    40120c <main+0x76>
4011f6:  lea    rax,[rip+0xe16]   # "Accès autorisé"
4011fd:  mov    rdi,rax
401200:  call   401070 <puts@plt>
Les commentaires # "%d" et # "Accès autorisé" sont ajoutés par moi : objdump affiche seulement l'adresse (402010, 402013). On les retrouve avec x/s dans GDB.

Un secret dans un binaire n'est jamais caché

✗ Ce qu'il ne faut pas faire

  • Écrire un mot de passe, une clé d'API ou un jeton dans le code source
  • Le « cacher » par un XOR, un encodage en base64 ou un découpage en morceaux
  • Compter sur la compilation pour le rendre illisible

✓ Ce qu'il faut faire

  • Vérifier le mot de passe sur un serveur, jamais sur la machine de l'utilisateur
  • Ne stocker qu'une empreinte (hash) salée du mot de passe, calculée avec un algorithme lent conçu pour cela (Argon2, bcrypt)
  • Ranger les clés d'API dans des variables d'environnement ou un coffre-fort de secrets
Tout ce que le processeur peut lire, un analyste peut le lire aussi. Le défi crackme du TP3 vous le fera constater.

Une empreinte est le résultat d'une fonction à sens unique : on ne peut pas retrouver le mot de passe à partir d'elle. Le sel est une valeur aléatoire ajoutée avant le calcul, pour que deux mots de passe identiques n'aient pas la même empreinte.

#4

Le dépassement de tampon

Débogage et rétro-ingénierie

Un programme vulnérable


#include <stdio.h>
void greet(void)
{
    char name[16];
    printf("Votre prénom : ");
    scanf("%s", name);   /* DANGEREUX */
    printf("Bonjour, %s !\n", name);
}
int main(void)
{
    greet();
    return 0;
}

La pile de greet

AdresseContenu
rbp + 8adresse de retour vers main
rbprbp sauvegardé
rbp − 16name (16 octets)

scanf écrit vers les adresses hautes. Après 16 caractères, elle écrase le rbp sauvegardé, puis l'adresse de retour.

✗ Ne jamais lire une saisie sans limiter sa taille.

Compilé sans protection : gcc -O0 -no-pie -fno-stack-protector. Dans greet, name est en [rbp-0x10] (vu avec objdump).

Écraser l'adresse de retour


$ ./overflow
Votre prénom : Cosmo
Bonjour, Cosmo !
$ ./overflow
Votre prénom : AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA
Bonjour, AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA !
Segmentation fault (core dumped)
  • Les 40 « A » (0x41) remplissent name, écrasent rbp puis l'adresse de retour
  • Au ret de greet, le processeur veut sauter à 0x4141414141414141 : adresse invalide, le noyau tue le programme
  • Avec des octets choisis au lieu de « A », un attaquant choisit où le programme saute : il prend le contrôle de rip

Dans GDB, au moment du plantage, x/xg $rsp montre la fausse adresse de retour : 0x4141414141414141.

C'est l'attaque décrite dès 1996 dans « Smashing the Stack for Fun and Profit ». Elle est toujours d'actualité dans les logiciels écrits en C et C++.

Les protections modernes

ProtectionPrincipeEffet sur l'attaque
Canari de pileune valeur aléatoire placée avant l'adresse de retour, vérifiée avant retle programme s'arrête : *** stack smashing detected ***
NX (pile non exécutable)la pile et les données ne peuvent pas être exécutéesimpossible d'exécuter du code injecté
ASLRla pile, le tas et les bibliothèques changent d'adresse à chaque lancementl'attaquant ne sait plus où sauter
PIEle programme lui-même est chargé à une adresse aléatoiremême effet pour le code du programme
Ces protections compliquent l'attaque sans corriger le bogue. La vraie solution : limiter les saisies (scanf("%15s", name), fgets) ou utiliser un langage qui vérifie les bornes (Rust, Python…).

Pour simplifier, les crackmes et démonstrations du module sont compilés sans PIE et GDB désactive l'ASLR : les adresses sont toujours les mêmes.

Démonstration : overflow-protected (compilé avec -fstack-protector-all) affiche « stack smashing detected » et renvoie 134 (SIGABRT). Les techniques de contournement (ROP, fuites d'adresses) sont pour le mastère.
#5

Le cadre légal

Débogage et rétro-ingénierie

Ce que dit la loi française

  • La décompilation d'un logiciel est autorisée, même contre l'avis de sa licence, lorsqu'elle est indispensable à son interopérabilité avec un autre logiciel, sous conditions (article L122-6-1 du Code de la propriété intellectuelle)
  • En dehors de ce cadre, reproduire ou analyser le logiciel d'autrui sans son accord peut constituer une contrefaçon
  • Accéder ou se maintenir frauduleusement dans un système informatique est un délit : jusqu'à 3 ans de prison et 100 000 € d'amende (article 323-1 du Code pénal)
N'analysez que des programmes que vous avez le droit d'analyser : les vôtres, ceux du cours, les épreuves de CTF, ou dans le cadre d'une mission autorisée par écrit.

Pour s'entraîner légalement : Root-Me (plateforme française), picoCTF, crackmes.one.

Insister : la compétence est la même pour l'analyste et pour l'attaquant. Ce qui les sépare, c'est l'autorisation.

À retenir

  • GDB : break *adresse, ni, finish, disassemble, watch, et set pour modifier registres et mémoire
  • gcc -S -masm=intel montre l'assembleur produit : prologue, variables locales sous rbp, épilogue
  • Les compilateurs remplacent les multiplications et divisions par des décalages et des multiplications
  • Analyse : file, strings, nm, puis objdump, puis GDB
  • Un secret écrit dans un binaire n'est jamais caché
  • Dépassement de tampon : écraser l'adresse de retour pour contrôler rip ; canari, NX, ASLR et PIE compliquent l'attaque
  • N'analysez que ce que vous avez le droit d'analyser
