Le module

Organisation du module

Pourquoi apprendre l'assembleur ?

Comprendre ce que fait vraiment la machine :

  • Le processeur n'exécute ni Python ni C : il exécute des instructions en binaire
  • L'assembleur est la forme lisible de ces instructions
  • Mémoire, pile, pointeurs, appels système : tout devient concret

Une compétence clé en cybersécurité :

  • Rétro-ingénierie : comprendre un programme sans son code source
  • Analyse de logiciels malveillants
  • Recherche de vulnérabilités et épreuves des CTF
Ce module prépare directement le parcours cyber du mastère. Personne ne vous demandera d'écrire un logiciel entier en assembleur, mais vous devrez savoir le lire.

Un CTF (Capture The Flag) est une compétition de sécurité informatique où l'on résout des épreuves pour trouver des « drapeaux » cachés.

Exemple parlant : un analyste qui reçoit un rançongiciel n'a jamais son code source. Il n'a que le binaire, donc l'assembleur.

Objectifs du module

À l'issue du module, vous serez capables de :

  • Décrire l'architecture d'un processeur : registres, unité arithmétique et logique, bus, mémoire
  • Écrire, assembler et exécuter des programmes simples en assembleur x86-64
  • Manipuler la mémoire : adresses, données, pile
  • Utiliser les appels système pour afficher, lire au clavier ou quitter un programme
  • Déboguer un programme instruction par instruction avec GDB, jusqu'à analyser un binaire inconnu

Programme

Cours 1 – Le processeur

Architecture de von Neumann, registres, unité arithmétique et logique, bus, premier programme, premiers pas dans GDB

Cours 2 – Mémoire et instructions

Sauts et boucles, adresses et tableaux, pile et fonctions, appels système et interruptions

Cours 3 – Débogage et rétro-ingénierie

GDB en profondeur, du C à l'assembleur, analyser un binaire sans son code source

Trois TP qui montent en puissance

TP1 : premiers programmes · TP2 : boucles, tableaux et fonctions · TP3 : le défi crackme, retrouver le mot de passe d'un programme inconnu

Un crackme est un petit programme écrit pour s'entraîner à la rétro-ingénierie : il demande un mot de passe qu'il faut retrouver en l'analysant.

En assembleur, une erreur ne produit souvent aucun message : le programme plante ou affiche n'importe quoi. Levez la main dès que vous êtes bloqués. Rester bloqué 20 minutes, c'est 20 minutes perdues.

Votre environnement de travail

  • Un Linux x86-64 dans le navigateur grâce à GitHub Codespaces
  • Tout est déjà installé : NASM (l'assembleur), ld (l'éditeur de liens) et GDB (le débogueur)
  • Rien à installer : fonctionne sur Windows, macOS (y compris les Mac à puce Apple) et Linux
  • Votre compte GitHub suffit, avec la double authentification activée
Au début du TP1, chacun crée son dépôt à partir de mon modèle puis ouvre son Codespace. Nous vérifions ensemble que tout fonctionne.

Le quota gratuit de Codespaces (60 heures par mois sur une machine à 2 cœurs) suffit largement. Arrêtez votre Codespace en fin de séance.

GitHub et Codespaces appartiennent à Microsoft et relèvent du droit américain (Cloud Act) : votre code est hébergé sur ses serveurs. Je les utilise parce que je les maîtrise et qu'ils évitent toute installation. Une machine virtuelle Linux, WSL sous Windows ou un hébergeur ouvert comme Codeberg font aussi l'affaire.

Pourquoi pas une installation locale : les Mac récents ont un processeur ARM, pas x86-64. Codespaces met tout le monde sur la même machine.

L'IA générative : autorisée, à une condition

  • ChatGPT, Claude, Copilot… sont autorisés pour les TP
  • Vous devez comprendre chaque ligne rendue : en séance, je peux vous demander d'en expliquer une
